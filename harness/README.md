# 内置提示词

统一查看和修改 [`prompts.toml`](prompts.toml)。每项都有用途、接收对象、注入时机、生效条件、原代码位置和正文。工具说明及参数描述也在此表；结构化协议、参数校验、权限与错误码仍由代码约束。

- `controller.*`：主控基础协议、消息来源、程序反馈和限定恢复。
- `tools.*`：模型看到的工具与参数说明；工具名称、JSON schema 和约束保留在代码中。
- `worker.*`：普通执行、只读续接与后端交接助手的职责。
- `manager.*`：迁移历史与续接摘要的来源说明。
- `workspace.*`：README/MEMORY 原文包装、产物约定和生成 README 的主动跟进文案。
- `housekeeper.*`：统一的事务摘要助手职责，以及主控接收摘要、判断跟进或静默的事件说明。

`text` 使用 TOML 多行 literal string，保留正文中的引号与反斜杠。动态参数写成 `{{name}}`，代码只替换一遍，不执行正文或递归展开传入内容。首次和后续巡视使用同一个摘要提示词，本轮时间范围、平台、覆盖与未读状态由程序提供的正文包决定。事务正文通过 `input_text` 直接注入摘要提示，`input_path` 仅标明保留的审计文件，无需助手调用工具读取。

运行代码通过 `src/harness.ts` 读取这份配置，并在后续取用时检查文件更新。已经提交的模型轮次不会被追改；模块启动时构建的常量、工具目录需重启桥后更新。Codex 已有原生会话的动态工具目录只在创建时登记，更新工具说明后应 `/new c`；基础指令继续使用原有建立、恢复和配置刷新流程。

工作区 `README.md` 通过 `init-workspace.ps1` 从模板渲染；模板里的 `{{harness.workspace.proactive_followup}}` 引用同一份正文，生成器不依赖 Node。已有工作区由部署流程按授权同步，生成器保留已有 README、MEMORY 和登记文件。`MEMORY.md` 是用户维护的正文，不自动搬入本表，也不覆盖。

`harness/` 是版本化运行资产，需随桥和远端执行器一起部署。隔离主控测试会同时核对源码、编译产物与提示词资产，避免测试和生产使用不同措辞。
