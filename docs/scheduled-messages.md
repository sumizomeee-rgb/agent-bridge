# 定时直接发送消息

`bridge_schedule_message` 保存时间、已授权目标和完整正文，到期由桥直接投递，不启动主控或执行助手，也不生成回复、添加模型抬头。登记操作仍由当前主控完成。

通过 `bridge_help` 按需展开参数，使用 `bridge_call` 执行：

```json
{
  "command": "bridge_schedule_message",
  "arguments": {
    "afterSeconds": 600,
    "targetId": "private",
    "text": "刚刚的方案还有一个待决定点，我们继续讨论吗？"
  }
}
```

`afterSeconds` 或带时区的 ISO `dueAt` 二选一，范围沿用现有计划的 1 秒至 30 天。`targetId` 来自当前 `bridge_delivery_targets`，`private` 表示当前 Bot 主人；不接受任意账号或其他聊天地址。正文保留原始空格、换行，最多 16000 字，不支持附件。发送仍经过平台格式适配和桥已有的敏感信息处理。

需要届时根据新进展判断、生成内容或派工，使用 `bridge_schedule_controller`；执行参数已确定的助手任务使用 `bridge_schedule_worker`。三个类型共用查询、改期和取消工具，注册回执不等于已经送达。

## 生命周期与回执

- 桥重启保留待发计划；桥离线、启动恢复或维护期间，不开始新的发送，恢复可用后处理到期计划。不是精确时刻送达保证。
- `/new`、`/cwd` 按既有规则取消旧会话计划；连续切换 Agent 保留计划及原投递目标。停止或切换期间的晚到登记会被拒绝。
- 接收人、主体、当前会话与群权限在登记及发送前核实。目标失效不改投其他入口；私聊、公开协作和内部协作的投递范围沿用即时消息边界。
- 发送前同步持久化领取，重复工具调用、并发轮询不会创建第二份计划或重复发送。
- 成功发送持久化 `completed` 及投递回执，并记入可见历史，不产生模型输入。中断后若已有确定送达回执，只补记完成；否则保留 `uncertain`，不自动重发。
- 明确的发送前拒绝为 `failed`；网络投递结果未知为 `uncertain`。直发消息的这两种状态在默认计划查询中可见，不改变其他计划原有的历史筛选，也不自动唤醒主控。

## 验证

固定测试覆盖原文、零模型调用、稳定调用 ID、并发、重启、回执未知、权限失效、取消、改期、重置、Agent 连续交接和维护排空。Host 集成测试走飞书与 Discord 的真实授权、目标冻结和持久回执代码，平台网络替换为隔离接收器。

`scripts/controller-lab/context-live.mjs` 的真实模型验收增加登记直发计划用例：指定测试主控通过实际入口登记，到期后隔离接收器收到一次原文，主控调用次数只增加登记这一轮，助手数不增加。不会向生产聊天发送测试消息。
