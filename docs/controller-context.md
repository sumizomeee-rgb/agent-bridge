# 主控上下文与按需工具

固定初始化从专用工作区的 `README.md` 开始。程序只展开其中登记的引用，不在末尾另加另一份桥协议、Agent 规则或 MEMORY。工程工作目录仍由 `workingCwd`、`/cwd` 决定，与上下文入口分开。

1. README 保存通用行为规则和引用导航。
2. `workspace/MEMORY.md` 载入用户原文，不由初始化助手摘要替代。
3. 主控工具包括一句话目录、交互约定以及两个原生调用接口；完整参数按需查询。
4. 每轮附带消息来源、受众、投递位置、时间、模型、事件与有界状态；任务清单、反馈和群现场沿原有触发条件提供。

README 与骨架保留 `{{bridge_root}}`、`{{workspace_root}}` 和 `{{include:...}}`，实际路径在初始化时解析。同版本模板在不同电脑保持相同；不解释 MEMORY 中的模板样式文本，不支持任意路径或递归引用。必要引用缺失、重复、未知引用、文件编码或大小异常会标记不完整，不能靠隐式拼接掩盖。

## 工具调用

新建 Codex 动态工具表与 Claude MCP 均只声明：

```text
bridge_help(command?)
bridge_call(command, arguments)
```

`bridge_help()` 返回短目录；提供命令名时返回当前启用登记的完整说明和 schema。`bridge_call` 按同一 schema 校验参数，再还原为真实命令，继续经过原有的授权、当前会话、功能开关、稳定调用 ID、场景更新、恢复限制及最终交付校验。它不绕过禁用工具，也不把参数错误变成传输失败。说明查询不执行管理动作，有单独的有界查询额度。

最终发送前完成管理和补充消息；确认最终送达后本轮封闭，只输出内部结束标记 DONE。普通文字输出不代替平台发送。真实私聊输入仍需回原私聊；群补充不替代私聊最终答复。群静默、后台直接结束、输入更新不重放及仅补发汇报的恢复限制沿用原有程序边界。

## 升级

生成器只补缺失文件，不覆盖现有 README、MEMORY、登记或凭据。旧工作区由部署方核对并更新 README，MEMORY 保留用户原文。仅替换编译产物不足以升级：须部署 `harness/`、骨架和脚本，并受控重启。

已有 Codex 原生会话不会在 resume 时重新登记工具表，继续接受旧直接调用以保持可用；要取得仅两个入口的新工具表和初始上下文，用 `/new c` 创建新原生会话。该命令的计划取消与历史续接行为保持。Claude 重启后按新 MCP 表续接；仍须通过工具实际调用验证，不凭普通回复判断。

## 验证

离线回归覆盖两端工具声明、完整说明、嵌套参数、禁用工具、无副作用查询、稳定调用 ID、交付封闭、输入更新与仅汇报恢复。生成器覆盖无 Node 环境、迁移目录和既有文件保留。

候选版本部署到隔离目录后，在部署机运行：

```text
node scripts/controller-lab/context-live.mjs --root <候选工程> --production-root <生产工程> --config <生产配置> --agent both --targets local
```

验收读取生产配置和默认助手，但不修改生产会话、开关或上下文；候选 README 与生产 MEMORY、登记和私有配置的受控副本组成隔离工作区。平台发送写入隔离 sink，真实主控使用 `gpt-6-luna xhigh`、`haiku xhigh`，真实派工沿保存的默认线路；普通 `/new`、介绍、工具发现、派工与结果回传走 Host/Bot/Manager/Native 原路径。源码、构建、提示词及工作区骨架参与一致性检查，测试结束核对生产来源哈希并清理测试凭据副本。

字符统计只代表桥装配文本和工具定义，不等同于模型 token、CLI 自带提示词、实际账单或长时间稳定性。工具说明改为按需获取，不能仅凭体积下降断言模型表现完全相同。
