# 使用说明

[返回项目首页](../README.md)

## 工作群与当前主控

正式配置为 v3，一个宿主启动 `startupProfiles` 中同平台的完整 Bot 集合。一个 Bot 只服务一个激活账号，该账号的私聊和多个工作群共用一个当前主控；Bot1、Bot2 的主控和上下文互不代用。身份以真实应用 ID、平台账号 ID 和本地明确映射为准，改 Bot 昵称不改变归属。

群收件需公共配置 `groupMode: true`，操作者在各 Bot 的白名单和 `principals` 中，并可核实负责人及各 Bot 的群访问权；飞书还需 `spaces` 逐应用地址登记。普通群执行授权只接受已激活负责人的真人输入；其他可见群成员的发言作为只读现场，不新增执行权限。未知账号、外部机器人和 Webhook 消息不能自行启动任务。

先在对应 Bot 私聊初始化，再明确 @ 一个 Bot 发送 `/group start` 激活或刷新工作群，指定一个收件入口并验证成员。`/group start` 沿用已有主控，不自动初始化其他未初始化成员；群 `/new` 可以显式批量建立新主控。负责人的普通群消息向全部已激活、就绪成员提供一次参与机会；真实提及、回复对象、正文姓名和别名都交给模型理解，不筛选收件 Bot。每个主控可自主回复或静默；控制命令保留独立目标规则。

群中只提供以下命令；模型、强度、Agent、目录、历史与宿主重启在 Bot 私聊管理：

| 群命令 | 操作 |
| --- | --- |
| `/group start` | 激活／刷新本群，核实负责人、Bot 成员与收件入口；沿用当前主控 |
| `/group stop` | 停用本群；保留主控、已授权任务和计划，后续结果不改投其他入口 |
| `/status` | 查看负责人、群绑定、成员当前主控与就绪状态 |
| `/workers [history] [details]` | 每个目标 Bot 使用与私聊相同的助手查询和卡片；不接受 `all`，不混成全桥任务清单 |
| `/new` | 批量重置本群成员；同时影响这些 Bot 的私聊和其他群，取消旧计划；不接受参数 |
| `/stop` | 停止本群成员的受管工作、队列和计划；同时影响其全部入口 |
| `/help` | 查看本群命令 |

群 `/new` 先核实各成员旧计划停止状态，再提交整批新绑定，各 Bot 分别初始化；准备失败不能显示整批成功。停止状态未知会保留待核对记录，不假称进程已退出。群公开记录和 Bot 进展是协作事实，不新增真人授权；后台结果保留原群、原任务和原目标，不转成私聊输入。群重连使用独立群游标：负责人输入按原授权边界恢复，其他可见群成员发言只恢复为现场，不使用私聊恢复，也不把 Bot 发言伪装为人类。

部署现场应分别核验首次真实 @ 激活及普通飞书群无 @ 消息实时投递；本项目的 2026-10-17 双 Bot 最小测试已通过，详细范围见唯一群聊设计稿。只读群 API 的核对结果不能替代模型调用、公开回复、跨 Bot 任务交接与重连等上线验收。

### 主控默认看到什么与查看历史

私聊与各激活群沿用本 Bot 同一个主控，每条消息自动带上真实来源；群轮自动提供有界近期／未读群现场。非白名单群成员的可见发言作为只读资料登记，默认不逐条唤醒主控；既非主人也非已登记 Bot 的其他群员（包括其他白名单真人）不会推进自动重判版本，但消息仍可读保存。未知或身份无法核实的机器人同样只作资料。白名单控制执行授权，不是过滤群讨论。旁观发言、引用和历史不能发起命令、派工或改变负责人。

群现场刷新由程序维护，不要求主控记一个计数或调用新的认领工具。最新设计在主控准备派工或公开发送前检查本轮输入后的可见新进展，只由本群主人、可核实的已登记 Bot 的公开消息以及本群已确认的助手派发／结束事实推进版本；其他群员的消息保留为可读现场，不因此打断旧响应或消耗刷新机会；有变化时先不执行旧响应，每个原始主人请求对每个 Bot 最多额外补送一次现场让模型重新判断；派生协作根及后续事件共享这份持久预算，重启不补满。随后新增消息正常排队，不无限重判，不取消已经运行的助手。自己已知的输出、服务回执和重复投递不自拦；其他群与内部正文不混入本群。刷新不会扩大原授权，也不能保证识别所有自然语言重复任务。实现与现场验收范围见[唯一群聊设计](group-controller-design.md#主控可见现场与慢响应刷新)。

需要了解更早消息时，主控可直接调用 `bridge_read_group_history`，按时间和分页读取真实群历史，包含非白名单成员与平台允许读取的 Bot 发言。群轮默认当前群，私聊须明确选择已激活群。结果标明发言者、时间、实际范围、分页和截断；权限不足会报告，读取不会重新派发历史任务或自动下载附件。

### 主控选择发送区域

同一个 Bot 的私聊和已激活工作群共用主控与队列，每条输入始终保留自己的来源。主控可用 `bridge_delivery_targets` 查询本人私聊及当前可访问的工作群，再通过发送工具的可选 `targetId` 明确选择投递位置；省略时回原入口。普通私聊向群发送须用 `finish: false`，本轮仍需在原私聊完成最终回复。发送到另一个区域不改变原任务的归属、预约、结果入口或未来默认地址。

统一的 `bridge_send_message` 向明确目标发送，默认确认送达后完成并封闭本轮；只有显式 `finish: false` 才作为补充发送，允许后续管理或最终回复。`bridge_send_user` 保留原入口最终回复的兼容用法；旧 `bridge_send_private` 只向当前群轮次已验证负责人投递，也默认最终发送，只有显式 `finish: false` 才补充发送。群轮还可用 `bridge_silent` 静默结束。因此群里可以只私聊负责人，普通私聊也可以补充投递到已激活群，再回原私聊完成最终回复。目标以真实身份和群绑定版本登记，发送前重新验权，失效目标需重新查询；未知投递不自动换调用标识重发。区域选择不会把 Bot 的跨区域发言伪造成真人群输入，也不自动触发目标群的新讨论。

## 主控与后台执行

能力入口由本 Bot 固定上下文工作区的 `capabilities/registry.json` 登记。桥启动或重启做本机静态前提检查，主控按需用 `bridge_check_capabilities` 过滤查询或刷新；网站登录、运行连接和交付另行实测，历史验收不代表实时就绪。任务进度来自真实工具活动，停滞提醒去重后交给主控判断，不自动取消或增加整体硬超时。细节见[能力登记与就绪检查](capabilities.md)。

在 `.local/config.json` 设置 `"controllerMode": true` 启用主控模式。主控直接处理聊天和读图；检查环境、操作浏览器、SSH、改代码等工作交给独立的 Codex / Claude 执行子 Agent。主控仅有桥提供的派发、续接、取消、查看、预约和公开回复工具；供应商、认证、模型别名沿用用户配置，电脑工具及用户 MCP 不加载到主控。

群派工的最新对齐是直接使用已有的派发、续接和预约工具，由桥自动登记负责 Bot、原授权、助手与资源归属；主控不再额外调用认领或完成工具，也不自行编造任务编号。群任务的短标题会进入群共享现场，应只写获准公开的必要内容，详细指令和内部正文不因此公开。桥依据助手实际状态维护执行结束；未知结果保持待核对，一轮结束不代表用户目标已经完成。已声明资源冲突仍拒绝，程序不根据任务文字猜测重复。

`internalBotCommunicationEnabled: false` 关闭 Bot 间后台递话、内部协作发起和依赖内部通知的交接；Bot 之间通过群公开交流，各自直属助手、群静默不回复及本人的私聊仍可用。关闭不撤回已进入上下文的旧内容，也不公开旧内部正文。修改开关后安全重启续接即可，不要求为此 `/new`；旧会话缓存的工具名仍受桥端拒绝。

新会话自动启动一次后台子 Agent，以本 Bot 固定上下文工作区的 `README.md` 为用户入口，遵循文件中定义的初始化入口、只读范围和回传要求；只有被明确列为初始化资料的本机文件才继续读取。桥不预设个人业务栏目，不扫描技能目录、连接远程电脑、联网检查或启动新工作。结果作为独立 `workspace-context` 事件交给同一主控会话，不拼入桥基础 prompt；已有相关问题可以据此补答。

显式 `/new`（含 `new chat`）在后台调查结果交给原主控后，由同一主控通过正常 `bridge_send_user` 通道主动回复一次：简短介绍它对当前工作区的理解、已确认的能力和待确认事项。复用这次完成事件，不追加一次模型调用，不伪造用户输入，也不把助手调查全文直接发出来。原命令确认先发送，介绍随后发送；持久状态防止重复和未知投递重试，停止或切换会话会取消旧介绍。首条普通消息、`/cwd`、`/agent` 初始化仍默认静默，已有问题可据调查补答。读取或介绍失败时由程序说明对应阶段。

初始化使用已有任务登记、计数与回执并异步执行，首条真实消息可能先于上下文到达；聊天不等待初始化，但未到达的工作区事实不能说成已载入。主控模式下 `/new`、`/cwd` 创建新会话并重新读取本 Bot 固定上下文工作区；`/cwd` 只改变工程执行目录；正常续接和重启按父会话持久标记去重，旧会话没有标记时补做一次。失败或结果未知不会反复自动重派。更新工作区文件后，新会话读取新内容，已有原生会话中的旧摘要不会自动刷新。

主控先完成派发等管理调用，再公开回复一次并结束当前轮。程序在公开回复开始前封闭该轮，拒绝后续派发、取消、续接和重复回复；只有下一条真实用户消息或后台事件才能开启下一轮。子任务完成会唤醒原主控继续处理。后续问题可以续接同一个子 Agent，也可以独立派发；同一子 Agent 的独立轮次串行，不同子 Agent 可以并行。`bridge_continue_worker` 忙时默认将补充交给当前原生轮次；`delivery: "next"` 明确排队下一轮，空闲时正常续接。Codex 使用 `turn/steer`；已核验的 Claude Code 2.1.76 使用持续 stdin、原消息 UUID 回显，在工具结束后的原生接收点并入当前任务，不杀进程再 resume。`pending`／`steering` 不表示送达，只有 `accepted` 表示原生确认；补充归属原 job，不另计任务。不支持、明确未送达或结果未知均不自动排队／重发，可查询接收记录；结果未知须先核查。独立停止仍使用 `bridge_cancel_worker`。同一 Bot、同一主人、同一私聊的新普通消息可在派工或发送前补入当前主控，最多额外续判一次；补入后不再重复排队，多条可以合答并保留各自回复覆盖，见下节。主控可安静地补查结果，再决定何时回复。 子 Agent 正常结束一轮不等于任务目标已达成，主控仍需核对结果；查询当前执行状态时读取实时登记，不能沿用先前的确认文案。原来的图片、附件、会话和模型切换继续使用。机器人的状态显示本 Bot 运行中的直属 Agent 数量和等待轮数；同一个 Agent 的排队轮次单独计数，预约与空闲会话不计数。普通主控私聊不再添加 ⏳／✅；文本斜杠和控制别名保留回执，Discord 原生斜杠仍正常确认。群与直接执行模式保持既有消息表情，数字表情不再更新。

主控单轮不设整体墙钟硬超时，不因轮次持续较长而中止 CLI 或将该轮标为失败；单条 RPC、网络请求、模型元数据查询的超时，以及显式取消、正常关闭和真实错误处理继续保留。

`bridge_list_workers` 默认保留全部子会话的身份、执行电脑、原生 ID 和运行／排队／接收状态，只附短结果预览；所有预览合计最多 8 KiB。需要某个子会话的结果或补充回执时，指定 `workerId` 查询详情；未确认回执完整保留，已结束回执只展开最近 20 条。完整结果、附件和会话仍保存在原有登记中。Codex 主控沿用 CLI 原生 compact 机制及用户配置，桥不修改压缩阈值。

`/stop` 停止桥管理的 CLI，并取消待处理任务及预约；已经发生的改动和子 Agent 自行启动的独立远端进程需要另行核对。`/new`、`/cwd` 会取消旧父会话的全部定时计划，停止其已启动的定时助手，并等待进程退出确认；无法确认时明确报错，暂不激活新会话。真实 `/agent` 切换使用连续交接，保留原助手和计划，不执行这一重置规则。定时任务的迟到结果仅保存，不唤醒或打扰新会话。普通工程任务仍可完成，旧结果只带来源通知。崩溃后正在执行的任务记为结果未知，对应子会话暂停，既不重做也不自动续接；排队任务保留。未开始的其他任务和预约可恢复。

首次切换运行模式会创建该模式的新原生父会话，保留旧记录、显式模型选择，并带入近期对话摘要。需要新会话是因为原生动态工具在建会话时绑定；不会把旧会话冒充为已经装好主控工具的会话。

普通私聊在下载图片前写入 `ingress.sqlite`，重连时补取已知私聊遗漏的消息。每条收件、子任务派发和公开回复都有持久记录，用于去重和恢复。已经执行或投递结果未知的内容不自动重发；Discord 投递失败会提示核对。

新增私有运行数据：`controller.sqlite` 保存子会话、任务和预约；`controller-homes/` 保存隔离的主控配置与原生会话；`controller-migration.json` 可提供按旧会话 ID 索引的迁移摘要。它们与已有数据库一起备份，不进入 Git。

### 普通私聊补送与合答

飞书与 Discord 共用同一规则：同 Bot、同主人、同私聊且已准备好的新消息，可以在慢响应准备派工或发送时补给当前主控；保留真实用户来源与图文顺序，最多额外续判一次，之后到达的消息正常排队。已经补入的消息不再各起一轮，多条可合答，每条普通私聊仍需被后续回复覆盖；群聊的静默能力不适用于普通私聊。

程序分别保存“消息已交给主控”和“回复已送达”。最终发送开始时冻结覆盖范围，发送期间新来的消息留待后续处理；补充发送、DONE、派工成功或后台结果本身不算完成回复。正文或附件还未准备好的消息不先消费；失败、取消和投递未知不会被假标成已答。控制命令、群消息、其他入口和主控切换形成边界，不跨越合并，也不把原来的动作自动重做。

普通主控私聊不再显示收件／完成表情；命令回执、群原有行为和直接执行模式保持。分类以持久原消息的正文和区域为准，重启后仍一致；没有修改平台总的 reactions 功能、助手计数或状态栏。详细权限与生命周期边界见[唯一设计](group-controller-design.md#普通私聊的续判与回复覆盖)。

## 两类定时计划

主控根据工作区的长期偏好，主动为已有事项安排合适的后续；无需每次等用户说“提醒我”。权限仍受原任务与用户长期约定约束，联系用户应具体、有用且适时。工作区模板提供跟进等通用行为规则，不给 Bot 预设职业或固定分工。称呼保存在各 Bot 的 Profile `aliases`，实际偏好由用户在本 Bot 的 README、MEMORY 和当前平台指南中维护。

| 类型 | 到点行为 | 适用情况 |
| --- | --- | --- |
| `bridge_schedule_worker` | 直接启动已保存的执行助手，结果再唤醒原主控 | 任务、电脑、模型与执行边界已经明确 |
| `bridge_schedule_controller` | 直接唤醒原主控，读取保存的提示再判断 | 提醒、复查进展、届时决定下一步 |

例如保存一个执行计划：`{"afterSeconds":3600,"title":"检查构建","prompt":"在既定项目只读检查构建结果，回报结果并结束","agent":"claude","model":"haiku","targetId":"local"}`。模型、强度、电脑、目录、图片和完整任务在登记时确定；等待期间不占 Agent 进程或运行数量，到点不增加一轮主控派工。

保存一个主控计划：`{"dueAt":"2026-10-16T17:00:00+08:00","title":"搬迁前核对","text":"依据原搬迁安排核对待办与截止时间；仍需用户行动时简短提醒，已完成则结束，不重复提醒。"}`。每轮会提供桥的实时时间；选择 `afterSeconds` 或含明确时区的 ISO `dueAt` 之一，距登记时刻须在 1 秒到 30 天内。主控应保存原目标、必要事实、预期动作和结束条件，登记成功后再承诺。

两类计划共用 `bridge_list_schedules` 查询（默认待触发或执行中，`includeFinished` 查看本会话历史，`scheduleId` 看详情，分页默认 20 条）、`bridge_update_schedule` 改期和 `bridge_cancel_schedule` 取消。改期仅限未触发计划，不改变类型或执行参数；已经启动的助手通过 `bridge_cancel_worker` 停止。计划保留原用户、聊天入口、工程目录和来源。只有同 Bot 的 `/agent` 连续交接会把它重绑到新主控，不能任意跨 Bot 或新会话接管。

重启桥保留未触发计划；离线期间到期的计划在恢复后执行。`/new`（含 continue）和 `/cwd` 会取消旧计划并停止已启动的定时助手，新会话不继承它们。真实 `/agent` 切换先暂停新计划触发，等待当前主控轮安全结束，目标主控准备成功后将普通助手、排队轮次、计划和完成事件重绑，再恢复触发；保留原聊天入口、工程目录与来源，不重跑已执行任务。切换失败恢复旧主控和计划。

助手计划状态为 `pending` → `running` → `completed` / `failed` / `cancelled` / `uncertain`；主控计划的 `triggered` 仅表示唤醒事件已登记，不代表模型已回复或消息已送达。事件投递沿用任务登记与公开消息的持久记录。启动恢复不会重放结果未知的执行，停止未确认时也不会宣称已经退出。执行入队与计划领取在同一事务完成，重复轮询和重启不会重复创建助手。

升级时，旧 `controller_wakes` 数据一次性转换为 `controller_schedules` 的主控计划，随后移除旧表和旧工具入口，不保留兼容别名。部署前备份私有数据库；已有主控需 `/new` 载入两类新工具（这也会按上述规则清空该旧会话的计划）。

## 切换 Agent 与新会话

主控模式中，私聊 `/agent claude`、`/agent codex` 只选择后端，聊天保持连续。真实切换时冻结本 Bot 当前主控的最新记录，由目标后端的独立只读助手提炼上下文，再让目标主控在禁止副作用的准备阶段载入交接。目标准备成功、持久提交和任务重绑后才激活；摘要或目标启动失败保持原主控。摘要助手的原生 ID 不给目标主控复用。选择已经激活的同一后端是无操作，不重复交接。

来回切换也始终交接当前最新上下文，不恢复目标后端较早的历史分支。普通助手、排队工作和定时计划保留，原聊天入口与工程目录不变；期间暂停新计划触发，运行中的普通助手继续工作。模型与强度按目标后端已保存选择、目标默认配置和实际元数据校验，不能把源后端的强度或实际模型猜给目标。

`/new` 建立新主控，默认不带旧聊天。`/new continue [codex|claude]` 只提炼**当前 Bot** 的最新主控历史，再与固定工作区初始化一起交给新主控；在 Bot1 私聊使用，就只读取 Bot1，不取 Bot2 或目标后端的旧分支。continue 仍属于重置：取消旧定时，不转移普通助手归属。群 `/new` 不接受 continue 或后端参数。

## 原生会话接管与单个 Agent 的选择

主控可用 `bridge_list_native_sessions` 查询当前桥电脑或 `remote-agents/registry.json` 登记电脑上的 Codex / Claude 原生会话，再用 `bridge_read_native_session` 查看有界摘要及状态。两者只读，不调用模型，也不派任务。原生历史默认只向桥的首个白名单用户开放；其他用户须在目标电脑登记的 `allowedUserIds` 获授权，机器人白名单本身不授予他人会话的访问权。

核实后用 `bridge_adopt_native_session` 传入真实原生 ID 和检查版本，建立空闲直属 Agent。它保持原 ID、原目录和完整原生历史；只有随后明确续接才运行 CLI，不会用摘要新建替代会话。`bridge_handoff_worker` 可将空闲会话交还用户，用户结束 CLI 后可再接管，旧 worker 只保留历史，不再派工。正在使用、结果未知、供应商不匹配或检查后已变化的会话会返回具体原因；先处理原因再重新查询。不要同时用人工 CLI 和桥操作同一会话。

`bridge_start_worker` 和 `bridge_continue_worker` 支持独立的 `model`、`effort`，例如派发 `codex`、`gpt-6-astra`、`low`，或 `claude`、`haiku`。参数原样提交对应目标 CLI，沿用用户的供应商与模型别名路由；不修改主控选择或全局配置。续接空闲会话时直接指定；忙碌时用 `delivery: "next"` 为下一轮选择，已运行的一轮不受影响。后续排队轮次不写参数时继承前一条排队选择。新建助手的 `model` 省略或填 `default` 时，同后端优先沿用主控显式选择，再取已确认的实际模型；跨后端使用桥的 `defaultModels`。未配置时仅查询桥本机对应 CLI 的默认元数据，无法确定则拒绝派发，不交给远端 CLI 决定。续接省略 `model` 保留该助手或最近排队轮的选择，显式 `default` 重新应用桥的上述规则；`effort: "default"` 仍清除强度覆盖。用户的模型别名原样提交，不根据实际网关模型改写别名。

工具更新必须按后端核验：Codex 旧原生会话的动态工具表仍需通过新会话加载，私聊 `/new continue` 可提炼最新上下文，但仍属于重置并取消旧预约；Claude 正常重启会重新提供当前 MCP 工具并续接原生会话，免于 `/new` 的结论须以相同 nativeId 实际调用新工具为证。接管的执行会话本身保持原 ID，不需新建。

## 直接执行模式的收件规则

配置未启用主控模式时，使用下述私聊直接执行行为。直接模式的 `/agent` 交接当前会话已保存的文字背景与排队输入，不运行主控模式的只读摘要和目标预载流程；群协作及受管助手／计划重绑需要主控模式。以下私聊命令表、附件声明和部署方式也供主控模式使用。

向原机器人私聊，直接发送文字或图片。空闲时首条已准备好的消息等待约 1 秒，将窗口内准备好的连续消息合成一轮；每条文字和图片保持收件顺序，每个原始 Discord 消息 ID 单独持久化去重。图片下载仍按同用户顺序准备，慢图片超过窗口时可能作为后续补充处理，窗口不会为持续输入无限延长。

Codex 执行时优先通过当前 app-server 的官方 `turn/steer` 把补充送进当前轮，不必等最终回复。准备/续接期间到达的消息会在 `turn/start` 确认活动轮后尝试补入。协议已用本机 Codex CLI 0.160.0 的 `app-server generate-ts` 核验：请求使用 `threadId`、`expectedTurnId`、有序 `input`，成功响应必须返回相同 `turnId`；参见 [官方 app-server 文档](https://developers.openai.com/codex/app-server/#steer-an-active-turn)。它不改变当前轮的模型、目录或权限，也不能保证立即打断已开始的工具操作，补充的消费时机由 Codex 决定。

活动轮已结束/取消、尚未就绪、投递回复期间，或旧 CLI 明确返回“无效请求/不支持方法/无效参数”时，补充可靠排入下一轮；同一轮首次明确拒绝后不继续尝试 steer。Claude 和没有 steer 能力的后端保持排队。忙中补充提供轻量“已收到/已交给当前任务/将排队”反馈，同会话最多约 15 秒一条；不转发逐字进展。直接执行模式的普通私聊消息收到后会添加 ⏳ 表情，表示已收到、等待处理或回复；最终回复及附件全部送达后，改为 ✅（添加完成表情，再移除沙漏）；主控模式普通私聊不使用这些表情。合并消息和已确认补入当前任务的消息一起更新；中间收件提示、Agent 刚完成但回复尚未送达、失败、取消或不确定的补充不会标成完成。表情请求独立发送，失败或限流不会阻挡消息处理；先收到的沙漏请求即使延迟，也会在完成更新前结束。原生斜杠命令沿用 Discord 自带的确认收到提示。

steer 超时（10 秒）、连接断开、内部错误、响应损坏或返回不同 turn ID 时，可能已被消费，记录为 `uncertain` 并提示核对，不自动重发。完成竞态会等待已发出的 steer 确认，成功补充归入当前轮；明确未提交的消息才接下一轮。所有发送中的补充先持久化为 `steering`，重启将其与 `running` 一起标记中断，不重做已经执行过的工具。执行 `completed` 和回复 `reply_state`（待投递/成功/失败/取消）独立保存，回复或附件投递失败不重跑 Agent；重启发现已完成但待投递的回复会提醒核对，也不重跑。

`/stop`、`/new`、`/agent`、`/cwd` 和新会话文字别名会越过慢图片准备及时处理，旧准备中的普通消息会持久化取消，旧轮迟到结果不能发送到新绑定。控制命令只使用文字选项，随命令附带的图片不进入 Agent；无效或重复控制命令也可能结束当前收件准备窗口，请单独发送普通图片消息。已开始的工具操作无法回滚。

`/workers` 与 `/computers` 使用黄色 ANSI 总览代码框，各助手或电脑独立编号、单独代码框；客户端即使不显示颜色，文字结构仍可读。长列表按完整条目分页，每段不超过 Discord 的 2000 字符限制。会话名适度截断，完整名称与回执可由主控按完整 `workerId` 查询；短 ID 沿用 workerId 前缀，至少 8 位，列表内碰撞时延长，条目保留完整 workerId 与原生 ID 供复制定位。

助手运行数只计已登记且有运行中 job 的助手；等待数是排队的助手 job 轮次，不含空闲历史会话、主控或预约唤醒。presence 显示“运行助手N”和“等待N轮”；现有主控 `/status` 的执行状态显示“主控处理1”，输入队列仍单独显示排队条数，presence 不新增主控计数。助手耗时取本轮 job 的开始时间，已完成轮次取其记录的结束更新时间；缺失或无法确认时明确说明，模型和强度只显示最近 CLI 实际回报，不用请求值替代。

电脑列表区分 SSH/本机连接、执行器 hello、CLI 静态入口、各后端直属派发准备和模型实测；入口就绪仅说明已有检查通过，未知字段保持未确认。本次显示层不增加健康探测或改变缓存。已运行的桥需要部署方安排受控重启才会加载这些修改。

Discord 官方说明：[多行代码框](https://support.discord.com/hc/en-us/articles/210298617-Markdown-Text-101-Chat-Formatting-Bold-Italic-Underline)、[消息内容长度](https://docs.discord.com/developers/resources/message#create-message)。黄色使用 `ansi` 代码框中的 ANSI 33 色及复位，不保证所有客户端显示颜色。

原生菜单的 `/effort` 使用 `level` 选项，例如 `level: xhigh`；留空查询，`level: default` 清除会话选择。

原生菜单的 `/agent` 使用 `agent` 选项；`/model` 使用 `name` 选项，例如选择 `/model` 后填 `name: gpt-6.1-sol`，或在 Claude 会话填 `name: haiku`、`sonnet`、`opus`。留空查询当前模型，填写 `list` 或 `default` 分别列出模型或恢复 CLI 默认；网关自定义 ID 可同时启用 `custom`。模型名称原样传给 CLI，别名映射完全沿用用户配置。

Discord 启动后按统一命令表同步私聊菜单，已激活工作群的服务器另同步群命令子集；不注册 `/resume`。飞书使用文字命令。命令先由 Discord 确认收到，再执行并回复同一交互；普通聊天和模型最终回复仍是私聊消息。注册失败会记录日志，不阻断普通私聊。菜单尚未刷新时可关闭再打开私聊，或直接发送上表文本命令。

图片和普通文件回传无需额外命令，直接说“截图发我”或“把文件发我”即可。工作目录的 `README.md` 约定：图片用 `![说明](<本地图片绝对路径>)` 声明，普通文件用 `[文件名](<本地文件绝对路径>)` 声明。初始化助手按 README 读取这些约定。桥原样提交用户消息和图片，不额外追加上下文或创建每轮产物目录，只解析最终回复中明确声明的文件并上传 Discord 附件。支持桥部署电脑上任意绝对路径的可读取物理文件，不限制在工作目录或历史产物目录；工位上的文件需先通过 SSH 下载到笔记本当前工作目录，再声明本地绝对路径。仅在需要实际回传附件时使用带尖括号的显式声明；技能说明或普通文件引用不要使用这种格式。普通文件必须使用带尖括号的显式声明；不带尖括号的路径链接及含 `:行号`、`:行号:列号`、`#L`、`#line` 定位后缀的源码引用保留原文。网页链接保留原文，代码示例不会触发上传。普通文件目前支持 Agent 发给用户；用户发给 Agent 的附件仍支持图片。

图片支持 PNG、JPG、WebP、GIF，每张最多 10 MiB（`maxImageBytes` 配置更小时沿用配置），以下载内容的文件头识别实际图片格式，文件名与声明 Content-Type 不一致时仍按真实格式接收；保存扩展名、模型 MIME 和图片路径 manifest 使用实际格式，图片字节不变。非图片内容仍拒绝，并提示附件已收到但未交给模型及具体原因。普通文件的 `maxFileBytes` 默认是 `20971520`（20 MiB），可配置为正整数字节数，上限 `25165824`（24 MiB）。每轮图片与普通文件合计最多 10 个、100 MiB，发送时每批附件最多 24 MiB。

这些是项目限额，实际上传还受 Discord 限制：[官方文件上传文档](https://docs.discord.com/developers/reference#uploading-files)目前列出单文件默认 20 MiB，可按目标上下文提高；[发送消息接口](https://docs.discord.com/developers/resources/message#create-message)的单请求上限是 25 MiB，包含正文和 multipart 开销。调大 `maxFileBytes` 不会提高 Discord 的实际额度，每轮 100 MiB 也不等于单请求可发 100 MiB。文件不存在、不是物理文件、图片格式无效、超过限额或 Discord 拒绝上传时会明确报错，保留原会话，不重跑模型、截图或其他工具。

私聊只允许已登记且在白名单中的激活账号；群输入按前述负责人、成员与权限检查接收。每轮发送最终回复，程序在正文前添加紧凑回复头，例如 `[Codex · 6.1-sol · 中 · b2c3]`。回复头省略模型的 `gpt-` 前缀，推理强度使用中文短标签，会话 ID 仅显示末 4 位；完整模型 ID 和会话 ID 保持原样。模型取本轮 CLI 回报，缺失时显示“模型未知”。推理强度由各 Agent 适配器返回统一证据结构，主控、执行助手、回复标题和总览共用同一显示规则：优先采用本轮明确回报，其次区分指定值与启动配置及来源；明确不支持才显示“不适用”，无证据显示“CLI 默认 · 未回报”。配置被启动过滤时标明“配置未采用”，不把配置值冒充实际回报，也不改用户 CLI 设置。会话尾号来自真实原生会话 ID；`/chats` 显示的桥会话短 ID 仅供查看，是另一种标识。

长回复按 Discord 长度限制分段，每段带同一个回复头；不会把逐字生成片段或工具协议发成消息。新会话会取消旧会话未完成的任务，迟到结果不会串到新会话。崩溃中正在执行的任务不自动重做，避免重复执行操作；重启后会提醒用户确认结果。

## 直接执行模式的后台 Agent 任务

主控模式由桥管理执行子 Agent 的派发、登记、完成通知和计数，主控使用内置管理工具；已登记的执行子 Agent 不再手动登记或生成完成回执。下面的手动登记方式仅适用于直接执行模式中父 Agent 自行启动的后台子任务。

本轮结束后仍需继续执行的本机或 SSH 子 Agent，由父 Agent 自己派发，并先登记任务、设置完成监听。桥不负责 SSH 派发，也不把普通任务自动拆成子 Agent；没有登记的后台进程不会计数或主动汇报。使用规则放在工作目录的 `README.md`。

桥启动父 CLI 时，仅通过 `BRIDGE_TASK_CONTEXT` 环境变量提供本轮的登记凭据文件。该文件包含 `nodePath`、`helperPath`；Agent 可用它们调用任务工具，不需要输入父会话 ID：

```powershell
$ctx = Get-Content -LiteralPath $env:BRIDGE_TASK_CONTEXT -Raw | ConvertFrom-Json
$job = & $ctx.nodePath $ctx.helperPath register --title '工位检查' `
  --exit-file 'E:\任务目录\exit.txt' --result-file 'E:\任务目录\result.txt' `
  --ssh-config 'C:\SuchProject\Other\ssh-project\hosts\11032022110008\ssh_config' --ssh-host administrator |
  ConvertFrom-Json
```

`register` 必须在父 Agent 本轮结束前执行。可在登记时直接附上监听参数，或之后用 `watch --task-id $job.taskId` 设置同样的参数。普通任务完成时先写 UTF-8 结果，再原子写入退出码文件；退出码 0 表示成功，非 0 会汇报失败。SSH 监听中的结果路径指向目标电脑，SSH 配置路径指向笔记本。

取消旧后台任务时，先使用对应 runner 停止并核实外部进程，再调用 `cancel --task-id <任务 ID> --text '取消原因及进程核查结果'`。`cancel` 使用当前 `BRIDGE_TASK_CONTEXT`，允许同一用户、同一会话跨轮取消旧任务，直接持久化取消状态并清除计数；不会停止外部进程。重复取消不会重复通知，已完成的任务不会改成取消。`watch` 和 `status` 仍需原注册轮次的上下文；不要用下一轮的上下文改旧任务监听。`complete` 仅生成签名回执文件，只有已登记监听读取该文件后才会更新状态，不能将“回执已生成”当作“取消已入库”。

也可使用签名回执：登记时指定 `--completion-file`，把登记返回的 `ticketPath` 复制到执行任务的电脑，再用仓库的 `scripts/task-complete.ps1 -TicketPath <票据路径> -OutputPath <完成文件路径> -Status completed -ResultFile <结果文件路径>` 生成回执；失败用 `failed`。有 Node 运行时的目标机也可调用 `task-cli.js complete --ticket ... --output ... --status completed --result-file ...`。每份票据只对应一个任务，不能用于登记新任务；上下文和票据是私有运行数据，不要发进 Discord 或提交 Git。

任务终态持久化后，桥会在父 Agent 空闲时续接原来的完整原生会话，让父 Agent 核对工具结果并主动回复同一私聊。普通用户消息优先；完成事件不会伪装成人类消息或新增用户授权。重复回执只汇总一次。`/new`、`/cwd` 或 `/stop` 会取消旧任务的自动续接，远端任务可以继续运行，完成后只发送带来源的结果通知。主控模式的 `/agent` 连续交接会重绑已登记任务，保留原入口和来源；不能把该规则套到任意新会话或其他 Bot。正在生成或投递汇总时崩溃，重启会提醒核对，不自动重跑。

主控模式的直属 Agent 计数显示在对应 Bot 的状态中，按 Bot 独立统计，不包含用户或任务名称。运行数量按正在执行的 Agent 去重，等待数量按排队轮次计；旧版没有执行开始时间的任务显示耗时未知。安全重启、恢复和失败状态优先显示。手机私聊是否展示此状态由 Discord 客户端决定，可随时用 `/workers` 查看精确数据；直接执行模式的手工后台登记仍可通过 `/status` 查询。原消息只保留 ⏳／✅ 收件与送达标记。

## 会话推理强度

`/effort` 只设置当前会话（主控模式中即当前主控）；直属子 Agent 的参数由主控通过派发工具管理，不增加用户逐个管理的菜单。强度选择写入桥会话数据库的 `effort` 列，不修改用户的 Codex/Claude 配置。旧数据库启动时增加可空列，历史原生会话和绑定保持不变。`/status`、`/model`、`/effort` 区分会话选择与最近 CLI 回报；选择后先清空旧强度回报，不能把“下轮提交”当作已生效。

Codex 从实际 CLI `model/list.supportedReasoningEfforts` 校验支持值；例如 GPT-6.1 Sol 支持 `xhigh`。Claude 从初始化元数据的 `supportsEffort`、`supportedEffortLevels` 校验，本机 CLI 2.1.76 接受 low/medium/high/max，不接受 xhigh。能力统一分为已支持的非空集合、明确不支持的空集合、缺证据的未知状态，并保留 CLI 来源与模型标识。只使用 CLI 明确返回的别名解析，不按名称猜网关能力；能力元数据也不证明网关实际执行。缺少有效模型强度元数据（含未知网关 ID）时拒绝显式强度；明确不支持时也拒绝，不擅自降档，可 `/effort default` 清除显式覆盖、沿用 CLI。模型切换若与已有强度选择不兼容会拒绝，需先设置兼容强度或恢复默认。目标后端不复制源后端强度，目标选择必须重新校验；每次显式强度执行前重新读取模型能力，配置重载也重新校验。执行/排队/切换设置期间拒绝强度修改。

Codex 使用原生 thread/start 或 thread/resume 的配置覆盖和 turn/start.effort；控制器选择变化重建其 CLI 进程、续接同一原生 ID，不要求 /new。每轮提交后读取 thread/read 的 reasoningEffort：这是 CLI 当前会话配置回报，不是服务端逐轮执行遥测。Claude 适配器处理自身 --effort、--resume、启动配置和明确 response.output_config.effort 回报；当前提供方没有该字段时，统一记录实际值未回报，不根据模型名或 thinking 文本猜测。不同后端不能共用未验证的强度参数；通用校验接受合法标识，具体可选等级只由该后端当前模型能力元数据决定。

`/model default` 同样清除显式覆盖，保存 `cli-default` 策略，不把查询到的模型 ID 固化；续接时只临时解析目标 CLI 当前默认，无法确认则明确失败。新可空 `model_policy` 列只标记新设置，旧原生会话未设置策略的记录保持原续接行为。Claude 主控读取外部 settings 时，仅透传本机已核对合法的持久 `effortLevel` low/medium/high；无效 xhigh 等字段不进入 `--settings`，源文件不改，max 仍只能在支持它的模型上作为会话参数使用。

同后端的新桥子任务按派发轮次显式 effort、父对话保存的 effort、父对话最近 CLI 实际回报的顺序继承；都未知时沿用目标 CLI 默认。跨后端新任务不复制父强度，使用目标 CLI 原生默认，不修改父会话或用户全局配置。`bridge_start_worker` 和 `bridge_continue_worker` 的新轮在入队与持久化前校验最终后端/模型/强度，不兼容不留新 worker/job，也不污染已有选择；执行前再次校验动态能力。忙时 current 补充不能改变模型或强度，只有显式 next 新轮使用独立参数快照；default 清除对应覆盖，后续省略继承最后排队快照。执行结果未知及未确认接管不自动重放。显式强度不兼容则明确失败，不强行提交参数。现有子任务和续接保留保存的指定强度，CLI 实际回报单独记录。旧版本把两者混存到 worker.effort，导致 CLI 回报可改变后续续接值；升级后以旧已保存值作为指定值，实际值先保持未知，首次新回报再记录。不能把近期某个 child 显示 xhigh 解释成所有旧任务已跟随父强度改变。同后端 /new、/cwd 沿用显式选择。

升级只编译不会改变已运行桥。待桥任务、排队消息和本轮控制器工作完成后，备份运行数据库，安排正常停启一次；启动会按当前统一命令表同步菜单。重启期间执行中任务会被取消或记为结果未知，因此不要在长任务运行中重启。上线后在机器人私聊用 /effort 查询，再设置 level 并发送普通消息，核对实际回报和原生会话尾号；Claude 未确认状态不能充作成功遥测。

## 安全重启

主控使用 `bridge_request_restart` 登记重启请求。独立监督进程先暂停新派发与预约触发，继续保存新收到的普通消息，等待已启动 Agent、正在处理的对话和消息投递结束，再重启并恢复原会话和队列。重复请求去重；未确认停止的进程不算安全窗口。远期预约和未启动队列不阻挡窗口。普通私聊中工具确认重启已安排后，当前主控仍须先向原私聊完成最终回复；等待重启期间仅允许这次收尾发送，不再接受新增管理动作，不能提前宣称已重启成功。

Discord 使用启用的统一状态显示准备重启、恢复和可用；飞书按 Bot 向最近有授权私聊联系人发送生命周期通知，不向群广播。可用通知在宿主和该 Bot 恢复完成后才发送，每次进程启动仅一次；Gateway 重连不冒充重启完成。`.local/data/restart.sqlite` 保存请求与阶段；启动失败保留错误记录；关闭 CLI 或连接失败时不启动第二个实例，监督进程停下并留下错误。使用 `scripts/supervise.ps1` 的独立登录监督任务才会自动重启；直接前台启动会明确返回需要监督任务。`stop.ps1` 仍表示手动停用，不用于自动重启。

主控与助手共用 effort 证据及显示规则，各后端和远端执行器只负责填充能力、指定值、启动配置与来源、本轮明确回报。每轮清空旧观测，模型变化后不会沿用另一个模型的能力。只有实际回报可显示为已确认强度；指定值、CLI 配置、环境配置分别标注来源，被过滤的配置也保留“未采用”事实。历史任务缺少记录时显示 `CLI 默认 · 未回报`，不以当前电脑配置补猜历史；`/workers details` 可查看各项证据。
