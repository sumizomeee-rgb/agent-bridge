# 命令、消息展示和生命周期

`src/commands.ts` 是两个平台共用的命令定义，包含参数、说明和用法。Discord 的原生菜单由它生成；飞书输入同名文字命令，进入同一个 SessionManager。`/help` 也由此生成，两个平台都有，没有飞书专用的业务命令。平台和 bot 只能在启动前通过 Profile 选择。

`/status` 只查询状态，不创建会话或调用模型。没有会话时也显示平台、机器人、Profile、模式、默认 Agent、目录和排队数量；模型选择与 CLI 实际回报分开，未回报不伪装为已生效。第一次发送普通文字或图片会自动新建该 bot 下的独立会话。

核心使用 `BridgePresentation` 描述标题、语义色、正文或条目及说明；不生成 ANSI 或平台卡片 JSON。Discord 渲染器保留绿色回复头、黄色电脑／助手总览。飞书使用 JSON 2.0 卡片，模型回复（包括新会话介绍）使用绿色标题，错误使用红色标题，警告及其余系统通知、命令、状态、帮助和总览使用橙黄色标题；正文支持 Markdown 和代码块，长回复分页重复标题，条目和元数据按文字展示，不触发提及。图片、文件仍作为附件按顺序发送。总览和状态字段在飞书使用原生 `plain_text` 组件保留换行，不把内部字段拼成 Markdown 段落。

`/computers` 默认按就绪程度排序，逐行标记各 Agent 的可派发、不可用和待确认；检查证据用 `/computers details` 展开。`/workers` 默认仅列执行、排队或待核对的助手，简要显示电脑／Agent／模型／强度／短编号、状态与耗时、任务名；`/workers history` 单独查看已结束或空闲的历史，可组合 `all`、`details`。完整 ID 和回执用 `/workers details` 展开。`all` 仍只访问当前 bot 下本用户的会话。

显式 `/new` 的初始化结果进入新主控后，触发同一次完成事件中的主动介绍，复用 `bridge_send_user`；成功介绍由主控生成，不追加一次模型调用或伪造用户消息。

`/new continue [codex|claude]` 复用这一个初始化助手，同时阅读工作区与桥冻结的上一会话材料。新会话和助手冻结相同的模型、强度；换后端时使用该后端的桥默认。材料只包含同用户、同入口的真实消息、确认送达的公开回复与任务快照，不包含推理过程、凭据或其他用户记录。历史早于公开回复正文日志的部分，从原会话隔离目录读取可确认送达的原生公开工具调用；Code Mode 记录只当文本读取，绝不执行。材料有读取和字节上限，缺失或截断会明确标注。

助手一次返回工作区摘要与续接摘要；后者目标 1500–2000 字、硬上限 3000 个 Unicode 字符，程序验证后写入 `.local/data/session-handoffs/<新会话ID>/context.md`。源快照、状态和摘要都是本地私有数据，不入 Git、不写 MEMORY.md。新主控收到同一个初始化事件后，简短说明接上的目标、关键纠正和待办。格式错误、超长或状态不明均按初始化失败处理，不伪称交接成功，不自动重做。

`/new` 与 `/new continue` 都先取消旧计划并确认已启动的定时助手停止，再切换；桥重启保留计划。旧普通助手保持原归属，续接摘要不自动重派旧任务或复活计划。`/new` 不携带旧会话摘要。Discord 菜单用布尔 `continue` 选项，飞书用同名文字参数，核心处理一致。

每轮主控输入和后台事件都附带简短的程序运行信息：后端、模型选择、实际回报、强度和助手默认规则。派工程序负责确定模型，主控不需要读源码或靠记忆猜工具默认值。更新后重启桥即可让已有会话受益；无需为模型修复另行 new。

`BridgeLifecycleEvent` 描述 draining、recovering、ready、failed。ready 只在平台连接、会话恢复及服务初始化完成后发布一次；长连接重连不触发它。生命周期标题来自共用文案：启动为“【桥】已就绪”，重启为“【桥】已重启”。Discord 通过在线状态显示“已重启”及汇总数量。飞书在 ready 时向当前实际 bot 最近收到消息的一个白名单用户发送黄框卡片，正文仅为“可以继续。”，已有会话保留；找不到联系人则不发送，不广播，也不跨 bot 借用联系人。

生命周期投递在 `.local/data/lifecycle.sqlite` 中记录。发送前记 attempted，成功记 delivered，失败或结果不确定记 uncertain；同一进程不会重复尝试，重连也不补发。通知失败不阻止桥继续处理消息。启动成功只代表连接与恢复完成，不代表模型提供方已通过实测。

飞书结构参照[卡片 JSON 2.0](https://open.feishu.cn/document/uAjLw4CM/ukzMukzMukzM/feishu-cards/card-json-v2-structure)及[Markdown 组件](https://open.feishu.cn/document/uAjLw4CM/ukzMukzMukzM/feishu-cards/card-json-v2-components/content-components/rich-text)。

程序错误和恢复提示统一由 `src/notices.ts` 生成，标题带 `【桥】` 短前缀，正文只给必要状态；Discord 使用红色标题，飞书使用红色错误卡片，无颜色的文本回退带 `❌`。CLI 完成报告与进程退出证明分开保存：退出失败不能覆盖报告，确认退出也不等于业务已验收，不自动解除核对锁或重做任务。

飞书每次公开投递在本 bot 的 `feishu-outbox.sqlite` 保存冻结内容、各条实际消息的 UUID、首次尝试时间和平台回执；网络失败最多补发一次，使用同一 UUID 和正文，且限定在首次尝试后 55 分钟内。已确认投递跳过，旧未确认投递不在重启后自动重发，也不重跑主控或助手。错误阶段、HTTP 状态和网络原因留在本地脱敏记录，聊天只显示短提示。

## 当前平台差异

会话、模型与强度、主控派工、电脑和助手查询、原生会话登记、重启恢复共用核心。以下为当前适配器的具体行为；“未实现”不表示平台本身做不到。

| 项目 | Discord | 飞书 |
| --- | --- | --- |
| 命令入口 | 原生斜杠菜单、参数选项，以及同名文字命令 | 当前仅同名文字命令；使用相同定义、参数和处理逻辑 |
| 收件与回复送达 | ⏳ 收件、✅ 回复已送达 | 思考中（`Status_PrivateMessage`）收件、勾号（`CheckMark`）回复已送达；同一语义，表情读写需应用权限 |
| 持续运行状态 | bot 在线状态显示全桥运行／排队数 | 未实现持续状态栏；通过 `/status`、`/workers` 查询 |
| 启动完成 | 在线状态显示“已重启” | 给当前 bot 最近联系的白名单用户发就绪卡片 |
| 消息展示 | 绿色回复头、黄色总览，正文使用 Discord Markdown | 语义相同的飞书卡片，原生标题色与正文 Markdown；分页长度由平台决定 |
| 普通文件输入 | 目前跳过非图片附件，随附文字仍可处理 | 目前明确报不支持，带普通附件的该条消息不交给模型；这部分仍待统一 |
| 图片、文件输出 | 支持图片和文件附件 | 支持图片和文件附件，按平台要求分别上传、发送 |
| 单张图片输入上限 | 20 MiB（还受本地配置限制） | 10 MiB（还受本地配置限制） |

普通文件“输入”指用户发给桥，不是桥向用户“输出”。两边已支持图片和普通文件输出。命令内容、参数与查询字段来自同一核心；平台只负责菜单参数编码和消息格式。

表情按用户指定的实际图案选择：蓝色省略号气泡和绿色勾号，不能用黄色思考脸 `THINKING` 或敲键盘 `Typing` 替代。官方[表情图案及标识](https://open.feishu.cn/document/server-docs/im-v1/message-reaction/emojis-introduce)。

飞书表情 API：[添加](https://open.feishu.cn/document/server-docs/im-v1/message-reaction/create)、[删除](https://open.feishu.cn/document/server-docs/im-v1/message-reaction/delete)。
