# 隔离主控验收

目的：使用真实桥的消息队列、主控适配器、派工 Runtime、执行适配器、任务回执和原生会话续接，检查问题发生在哪一层。真实链路集读取实际部署的 CLI、认证路由、工作区电脑登记、预设和默认助手；生产数据库仅以只读方式读取默认助手设置表，不读取生产会话或任务。测试主控会话、任务队列和输出独立，不连接聊天平台，不更改生产主控模型。远端沿实际 SSH、自动部署和执行器协议运行只读测试任务。

先构建，再运行固定故障集（不调用模型）：

```powershell
npm run build
node scripts/controller-lab.mjs
```

防构建漂移是强制门槛：每次启动会使用当前源码与 tsconfig，在本次隔离目录重新编译参考产物，然后比较 `dist/src` 的完整文件集合和 SHA256；固定测试还比较 `dist/test`。旧构建、残留文件、缺文件均拒绝运行，不调用模型。结束时再次检查源码及待测运行时未变化，变化则整轮失败。源码、依赖清单和运行时散列写入报告。参考编译不覆盖待测代码。

`--runtime-root` 指向仅有构建产物的候选目录时，必须用 `--source-root <对应源码目录>` 指定源码及 TypeScript 编译器所在目录；不能只凭五个文件的散列或同一个提交号宣称一致。此检查证明待测产物对应所选源码；证明正在运行的生产进程版本，仍需上线时核对该进程加载的发布版本。

真实模型集需要明确指定配置；默认只测试已授权的 Codex `gpt-6-luna` + `xhigh`：

```powershell
node scripts/controller-lab.mjs --live --config .local/config.json --agent codex
node scripts/controller-lab.mjs --live --config .local/config.json --agent claude
# 真实配置专项：两个指定主控，实际电脑/预设/默认助手/SSH/执行器，独立会话和接收器
node scripts/controller-lab.mjs --live --selection-only --config .local/config.json --agent both
# 可缩小实际目标或指定测试主控；不指定 targets 时逐台检查登记电脑
node scripts/controller-lab.mjs --live --selection-only --config .local/config.json --agent codex --targets local,workstation --controller-model gpt-6-luna --controller-effort xhigh
```

Claude 请求 `haiku` + `xhigh`。模型别名按用户现有网关偏好解析；测试只记录 CLI 回报，不阻止用户的模型映射，不修改路由或自动换模型。先向实际 CLI 查询 effort 能力。`--agent both` 顺序测试两个后端；并发压力不是这套默认验收的目的。

脚本可独立复制到目标机器，用 `--runtime-root` 指向已构建的桥，验证那台机器的 CLI、认证路由和运行时代码。每轮在该根目录的 `.local/controller-lab/<时间-进程号>/` 创建新目录。报告记录运行时代码散列、请求/回报模型、effort 证据、生命周期、真实执行次数、回复及清理状态。没有回报的实际 effort 不推断为 xhigh。测试用认证副本在确认进程关闭后删除；若关闭失败，保留现场并报告，不能声称全部通过。报告与测试会话不是可公开上传的数据包。

固定故障集覆盖：已观察到 CLI 退出且没有最终报告的预设执行失败（含 413）在本机和 SSH 路径均落为失败并回报具体错误；取消旧排队指令，只允许新核查指令续接，413 指引精简交接另起助手。重启恢复同样核验退出证据；缺少证据、已有业务报告的结果未知及清理失败仍保留保护。这些是受控故障注入，不代表已复现真实网关的请求大小限制。另覆盖：未提交时的一次恢复、提交确认丢失不重放、已接收失败不重派、未知进程退出不重叠启动、缺少最终回复时的一次补齐、已确认回复与退出错误分开、自动恢复/补答不发过程通知、恢复失败只发最终错误、正常启动/重启完成保留原有通知、正常慢执行不警告，以及执行中追加消息的队列边界。另覆盖已完成助手结果汇报前的恢复、汇报明确失败后的单次受限续接、未知投递不重发，以及维护停机等待正在进行的汇报。

新增默认固定验收：三个续决策入口（私聊追加、群现场重判、遗漏回复补救）分别注入当前轮接单但丢 RPC 回执、仅迟到旧轮接单、明确拒绝，验证不会误停、串轮或重复派工。

群聊整链覆盖飞书和 Discord 的 HostRuntime → BotRuntime → SessionManager → NativeControllerAdapter → ControllerRuntime → 任务结果回群。仅平台 I/O、CLI 协议和执行器结果使用替身；生产编排与持久化代码不另写一份。用例从已有 native ID、缺少初始化日志开始，验证普通群消息不额外初始化、默认模型继承、现场重判、结果原群投递，以及退出未确认时不重叠启动、获得停止证明后下一条普通输入沿用原会话。原有宿主群聊与 Bot 生命周期测试也纳入默认集。这是固定协议测试，不冒充真实模型群聊或真实飞书网络验收。

Windows 停机测试使用真实隔离进程树：无响应且未获得 STOP 授权的辅助进程可安全回收并换用备用；一旦已发送 STOP，就不启动并行终止操作。优先使用已安装的标准路径 PowerShell 7，未安装则使用 Windows PowerShell。两次都未能确认时仍报告未知，不能假装进程已停。

真实模型集覆盖：冷启动→一次真实子 Agent→结果唤醒主控→本地回复回执；热会话执行工具时收到追加输入，并保持工具等待 3 秒检查没有过程提示；关闭后从同一持久化 native ID 续接并回忆旧结果；重复投递同一个平台消息 ID 不再执行、不重复回复。派工必须省略 agent/model/effort，测试脚本不补参数，检查真实 Runtime 继承主控后端、模型和 xhigh。这部分本机故障测试使用指定低价子 Agent，禁用业务工具，任务计算 17+25。真实配置专项另外使用实际默认助手（包括用户已配置的预设模型），并逐台验证所选后端的普通派工；测试主控仍按指定模型启动。只读任务仅返回 hostname、当前时间和唯一测试标记；不访问业务、操作浏览器或派生助手。主控会话和任务队列独立，远端执行器沿生产隐藏会话协议为每个测试 worker 创建独立运行目录。

真实模型故障矩阵（与固定协议替身测试分开）：

| 隔离注入/边界 | 验收要求 |
| --- | --- |
| 已完成助手汇报收到明确失败 | 仅续接一次，真实模型汇报已保存的 42，保持 native ID，不派工 |
| 汇报恢复时再次明确失败 | 两次注入都命中；终态为失败，不能无限重试或假装成功 |
| 普通用户请求已接收后明确失败 | 不自动重放原请求；下一次独立输入仍能回复 |
| 发送前校验拒绝 | 实际模型纠正后仅投递一次，无重复派工 |
| 投递回执不确定 | 仅一次投递尝试，失败保留，不自动补发 |
| 汇报传输断开 | 不重放汇报；下一次独立输入能回复 |
| Codex 初始化响应丢失 | 真 CLI 响应被丢弃，触发真实超时；未提交时只重试一次，最终仅提交一次 |

协议故障由 `faults.mjs` 在真实 CLI 与桥之间注入，记录 `source=lab-injection`、命中次数、生命周期和投递尝试。Claude 明确失败由测试器在转发输入后注入失败结果，并非声称网关真实返回了错误；Codex 在真实提交确认后注入失败。故障后的恢复回复由真实模型生成。汇报故障复用本轮真实子任务的保存结果，直接验收 NativeControllerAdapter 边界；不冒充生产任务数据库重放或平台网络测试。每个独立故障即使失败仍保留结果并继续后续用例，不自动重跑覆盖失败。

复用已汇报结果前，先通过真实主控会话明确授权独立演练汇报，并保留真实结果的 source 路由；每次使用不同 LAB_CASE，避免将重复旧报告被静默忽略误判成恢复缺陷。缺少最终回复仍由固定故障集验证：尝试仅用提示词要求真实模型不回复时，模型可能遵循桥系统规则直接发送，未进入补答路径不能算通过；该尝试的失败报告保留，不列入真实模型覆盖。

测试时 240 秒等待上限仅用于结束验收和报告失败，不更改生产超时，也不产生用户黄框。固定测试通过与真实模型测试通过分别记录；失败不靠换模型、自动降级、重跑覆盖。冷启动首次失败后恢复成功仍保留原始生命周期，不能称初始化故障已经消失。

维护停机使用 `pwsh -File stop.ps1 -Drain -WaitSeconds 300`。宿主先暂停接新轮次，再等待进程内的主控、任务汇报和执行器空闲。超时只报告仍在等待，不强杀；普通 `stop.ps1` 仍保留主动停止语义。`-Drain` 会核对当前 PID 凭据的支持版本；旧宿主不支持时拒绝请求，不能退回快照空闲检查冒充排空。

真实配置专项使用 HostRuntime → BotRuntime → DurableIngress → SessionManager → NativeControllerAdapter → ControllerRuntime → 实际执行器 → 结果回传，平台收发替换为隔离接收器，测试 Bot 身份与锁独立。电脑登记、预设、认证路由和用户默认设置读取实际配置，不再替换 TargetCatalogService 或编造远端电脑。启动检查和派工前检查复用 RemoteDeploymentService；由真实主控调用工具，验证持久化 worker、目标电脑、预设选择、实际模型回报、任务完成及退出证明、结果唤醒主控，并核对 `/workers` 隐藏已完成项、`/workers history` 保留历史。未设置远端默认时必须拒绝并且不创建 worker。普通派工另走实际登记引擎的指定测试模型。每台电脑独立记结果；离线、阻塞或超时记失败，不能跳过后汇总为通过。配置和产物散列随报告保存。

固定集限制同时运行两个测试文件，避免 Windows 进程启动测试互相挤占资源；这不改变生产并发。

新增固定故障：执行器主进程退出但后代仍活着时，真实 Windows 启动脚本必须继续拉起主进程；计划任务显示 Running 但执行器离线时，仅在日志证明空闲、启动脚本身份一致且没有执行子进程时回收该脚本。忙碌、有子进程、PID 身份变化或多个启动脚本时不回收。最终回复若在并行管理调用返回前写好，待调用结束后拒绝旧稿，要求主控读实际回执再回复；不自动重派，不新增过程黄框。

验收边界：消息接收器代替飞书/Discord 网络；真实配置集覆盖实际登记的跨机派工，报告逐项注明通过或失败。仍不覆盖真实平台投递、已有生产长会话、浏览器/业务工具和跨日稳定性，不能据此承诺“所有非 LLM 问题已排除”。固定协议集、本机模型故障集与真实配置集分别报告，不互相冒充。
