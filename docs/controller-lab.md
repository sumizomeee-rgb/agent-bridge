# 隔离主控验收

目的：使用真实桥的消息队列、主控适配器、派工 Runtime、执行适配器、任务回执和原生会话续接，检查问题发生在哪一层。生产配置只用于读取 CLI 命令和认证/模型路由，不连接聊天平台，不打开生产数据库，不更改生产模型。

先构建，再运行固定故障集（不调用模型）：

```powershell
npm run build
node scripts/controller-lab.mjs
```

真实模型集需要明确指定配置；默认只测试已授权的 Codex `gpt-6-luna` + `xhigh`：

```powershell
node scripts/controller-lab.mjs --live --config .local/config.json --agent codex
node scripts/controller-lab.mjs --live --config .local/config.json --agent claude
```

Claude 请求 `haiku` + `xhigh`。模型别名按用户现有网关偏好解析；测试只记录 CLI 回报，不阻止用户的模型映射，不修改路由或自动换模型。先向实际 CLI 查询 effort 能力。`--agent both` 顺序测试两个后端；并发压力不是这套默认验收的目的。

脚本可独立复制到目标机器，用 `--runtime-root` 指向已构建的桥，验证那台机器的 CLI、认证路由和运行时代码。每轮在该根目录的 `.local/controller-lab/<时间-进程号>/` 创建新目录。报告记录运行时代码散列、请求/回报模型、effort 证据、生命周期、真实执行次数、回复及清理状态。没有回报的实际 effort 不推断为 xhigh。测试用认证副本在确认进程关闭后删除；若关闭失败，保留现场并报告，不能声称全部通过。报告与测试会话不是可公开上传的数据包。

固定故障集覆盖：未提交时的一次恢复、提交确认丢失不重放、已接收失败不重派、未知进程退出不重叠启动、缺少最终回复时的一次补齐、已确认回复与退出错误分开、自动恢复/补答不发过程通知、恢复失败只发最终错误、正常启动/重启完成保留原有通知、正常慢执行不警告，以及执行中追加消息的队列边界。另覆盖已完成助手结果汇报前的恢复、汇报明确失败后的单次受限续接、未知投递不重发，以及维护停机等待正在进行的汇报。

真实模型集覆盖：冷启动→一次真实子 Agent→结果唤醒主控→本地回复回执；热会话执行工具时收到追加输入；关闭后从同一持久化 native ID 续接并回忆旧结果。所有子 Agent 也限定为所选低价模型和 xhigh。执行器走真实协议，但禁用业务工具；任务只需计算 17+25。工作目录、SQLite、主控 home、执行器 home 都独立创建。

测试时 240 秒等待上限仅用于结束验收和报告失败，不更改生产超时，也不产生用户黄框。固定测试通过与真实模型测试通过分别记录；失败不靠换模型、自动降级、重跑覆盖。冷启动首次失败后恢复成功仍保留原始生命周期，不能称初始化故障已经消失。

维护停机使用 `pwsh -File stop.ps1 -Drain -WaitSeconds 300`。宿主先暂停接新轮次，再等待进程内的主控、任务汇报和执行器空闲。超时只报告仍在等待，不强杀；普通 `stop.ps1` 仍保留主动停止语义。`-Drain` 会核对当前 PID 凭据的支持版本；旧宿主不支持时拒绝请求，不能退回快照空闲检查冒充排空。

验收边界：本地消息接收器代替飞书/Discord 网络；没有覆盖真实平台投递、三个电脑之间的远程执行、已有生产长会话、浏览器/业务工具和跨日稳定性。因此不能据此承诺“所有非 LLM 问题已排除”。修改触及这些层时还需相应的独立验收。
