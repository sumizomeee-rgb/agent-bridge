# 飞书聊天平台能力

本文件说明飞书 Bot 的操作入口和选路方法。它是能力导航，不是当前权限证明；不在这里保存 appSecret、Token、Cookie、个人账号或实时连接状态。

## 初始化只读范围

仅当桥提供的当前平台为 `feishu`，且工作区 README 将本文件列为初始化入口时读取。把接口入口、适用场景、核对方式和未知项提炼给主控，不加载 Discord 文档，不联网探测或执行消息、建群等操作。平台未知时报告缺失，不按 Bot 名称猜测。 主控只接收能力、适用场景、执行文档路径与未知边界的简要概括；本文件全文、接口参数和操作步骤由执行助手按任务读取，不复制进主控初始化回执。

## 方法选择

| 需求 | 优先考虑的入口 | 实际执行前核对 |
| --- | --- | --- |
| 确认 Bot 身份及显示名 | 飞书机器人信息接口 | 当前 applicationId；显示名只用于展示 |
| 查看已激活群近期历史 | 主控 `bridge_read_group_history`，底层飞书消息历史接口 | 当前群或明确选择的已激活群、真实发言者／时间、权限与分页；历史仅作资料 |
| 查询群、群主与成员 | 飞书群组及群成员接口 | Bot 是否在群、真实 chat_id、用户 ID 所属应用与结果分页 |
| 已授权的建群或添加 Bot | 飞书建群及成员接口 | 明确的目标成员；不凭同名推断身份；回读实际群主及人／Bot 数量 |
| 发送、回复及核对群消息 | 飞书消息接口 | 发送 Bot、固定目标群、原请求授权；用 message_id 回读结果 |
| 图片与文件交付 | 飞书上传与消息接口，或已有桥附件出口 | 上传身份、文件类型和大小、目标受众及实际发送结果 |
| 接口未覆盖的个人账号或页面操作 | 已登记的飞书网页／桌面入口 | 对应登录会话、桌面状态和工具能力，不能用 Bot 认证冒充个人账号 |

接口支持需求、权限已有且能核对结果时，优先考虑接口，避免无谓地远程打开网页。接口不支持或权限不足时，再权衡已登记的网页／桌面方式；不要反复尝试共享同一阻点的路线。

需要负责人本人发言、真实选择 @ Bot 或验收群事件时，优先由助手操作已有登录的飞书网页版，在当前明确授权的群与内容范围内自行完成；仅在登录或工具受限时请用户配合。Bot 接口不能代替个人账号，手写昵称和直接向桥注入合成输入也不能代替平台真实提及与真人消息验收。

## 浏览器异常与正常重启（执行助手按需读取）

初始化给主控只保留一句浏览器结果核验原则和本文件路径，不回传本节完整步骤。以下是排查与验收方法，不代表故障永远来自同一原因，也不增加操作授权。

1. 先确认执行电脑、实际用户及已有登录的 Chrome profile，保持原登录会话。分别判断是工具／MCP 连接中断、网页加载未完成、登录过期，还是接口业务失败；一种失败不能证明其他能力不可用。先按当前任务检查页面、刷新或重新进入已知入口，给页面合理加载时间后再核验；初始 snapshot 不是最终网页状态。
2. 若刷新和入口恢复仍失败，并且当前任务授权允许正常重启浏览器，先检查实际可见的未保存编辑或提交提示：有明确未保存内容先保留，无法保留时报告具体阻点；无明确阻点时正常关闭目标 Chrome，已有正常重启授权时不因假设风险重复询问。核对旧主进程确已退出、该用户目标浏览器的 Chrome 进程已清零；存在其他用户或不明确的 Chrome 进程时先辨明归属，不把别人的会话纳入关闭范围。未清零或无法确认退出就报告阻点，不宣称重启完成。
3. 用同一用户、同一 profile 正常启动 Chrome，记录并核对新主进程 PID 与启动时间，确认它是本次新启动的进程；不可只凭窗口重新出现判断。重新连接工具／MCP，确认其绑定的是目标电脑和目标浏览器。
4. 打开原飞书入口，等待实际加载后读取真实会话列表和目标会话 DOM，并查看截图，确认内容可见、登录状态和所需操作能力。报告分别列明进程重启证据与网页恢复证据；没有网页证据时只能说明进程已重启。需要发送或更改内容仍按原任务授权，不能为恢复测试擅自向他人发消息。

`chrome://restart` 导航、工具返回 `Target closed` 或 MCP 断连本身都不是重启或恢复成功的证据。内部 `chrome://version` 页面或 CDP 访问被工具权限拒绝，不代表飞书站点工具坏了；需要确认版本时可按当前电脑支持的方法读取进程模块或可执行文件版本，不反复撞同一权限阻点。

默认不清 Cookie、不换 profile、不改代理、不强制 kill 浏览器，也不重启电脑；确有必要时另按用户授权处理。正常关闭如被未保存内容或工具能力阻止，应报告具体阻点及已有证据，不把“已尝试”写成“已成功”。

## 群现场与提及映射

飞书群以真实 `chat_id` 标识一个现场；个人私聊与群可见范围分别记录。普通群消息的共同收件与自主静默遵循桥的主控协议，不由本平台文档另设按名字或 @ 过滤的规则。真实提及与回复关系应保留给模型理解，正文称呼不能冒充平台提及实体。

提及身份属于观察应用的 ID 空间，同一人或 Bot 在不同应用下的 Open ID 可能不同；按已核验应用／群映射还原实际发言者和提及对象，无法证明时如实标未知，不猜成其他 Bot 或全员。这种身份核对不把普通主人群消息缩成仅向被提及者投递。

## 身份与执行入口

- 真实身份使用 `feishu:<applicationId>`。部署 Profile 建议以固定应用 ID 命名；可变显示名和用户别名只作为登记索引。实际入口在工作区的部署导航与私有 Bot 登记里，模板不绑定某台电脑或某个应用。
- Bot 凭据在所选部署的 `.local/bots/feishu/<固定标识>.json`，只能由已获任务授权的执行者在原电脑上按需读取和使用；初始化不读取凭据，不把它们放进摘要、记忆、日志或聊天。
- 飞书应用身份与个人网页登录身份不同。不同应用下同一人的 Open ID 不同，不能把一个 Bot 的白名单值直接复制给另一个；按已核对的用户映射、群主及成员证据确认。
- 主控使用当前实际开放的工具，或委派已登记执行 Agent 操作。文档和新建文件不会增加主控工具、开通权限或启动平台监听。

## 就绪与结果

能力入口及历史验收放 `bridge-capabilities/registry.json` 或部署明确登记的操作入口中；当前注册表不支持的 API 类型不能伪装成浏览器已就绪。区分“接口有此功能”“凭据可鉴权”“当前权限通过”“真实发送／回读通过”和“桥已接入群事件”。

发送前固定 Bot 和 chat_id，使用稳定请求标识；发送结果未知时先查证，不直接重发。HTTP 成功不等于消息内容、成员或附件已正确交付，应核对业务返回码、真实 ID 和必要回读。
